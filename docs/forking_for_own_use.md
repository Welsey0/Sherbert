# Forking for Your Own Use
You are welcome to fork STK tooling for your own modpack projects. If you reuse this tooling, please credit this repository.

## Step 1: Set Up Development Environment
Follow [DEVELOPING.md](../DEVELOPING.md) first.

## Step 2: Understand the New Flow
This repo uses:
- `packinfo.toml` as a config file for the whole pack.
- `src/` as base content. (configs, manual jars, etc)
- `src-*` temporary loader folders generated by STK.

Loader folders are often deleted once a build is complete and are not intended to be persistant.

## Step 3: Forking Paths
### Keep Sherbert content as a base
If you decide to build your pack upon Sherbert, remember to update the pack's metadata in `packinfo.toml`. The ModpackUtils config folder and Sherbert Colors resource pack are also both intended to be used only in Sherbert, so please don't reuse those.

### Start a new pack from tooling only
STK includes a command, `setup-workspace`, that helps with this. It will replace Sherbert's files with blank templates for your own use.

```
python3 stmanager.py setup-workspace
```

## Step 4: Modrinth Setup
The workflows in this repo are designed for publishing on [Modrinth](https://modrinth.com). You'll need to have a Modrinth account and project ready.

Helpful support links:
- [Modpacks on Modrinth](https://support.modrinth.com/en/articles/8802250-modpacks-on-modrinth)
- [Sharing Modpacks](https://support.modrinth.com/en/articles/8797522-sharing-modpacks)

## Step 5: GitHub Secrets and Permissions
Create these repository secrets:
- `MODRINTH_TOKEN`
- `MODRINTH_PID`

Recommended PAT scopes:
- Write projects
- Create versions
- Read versions
- Write versions

Also make sure to set repository workflow permissions in the GitHub repo settings so that GitHub Releases can function properly.
